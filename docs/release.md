# Выпуски и автообновление

## Как устроено

- Каждая правка проверяется в GitHub Actions (`CI`): формат, clippy,
  тесты в Linux и Windows, сборка установщика и его проверка на чистом
  Windows — установить, запустить, обновить поверх запущенной программы,
  удалить. Снимки экрана лежат в артефакте `screenshots`.
- Когда в `main` попадает новая версия (номер в `Cargo.toml`, которого ещё
  нет среди выпусков), сам запускается `Выпуск`: собирает установщик,
  подписывает его и публикует на странице Releases.
- Программа при запуске спрашивает GitHub о последнем выпуске. Если он
  новее, сверху появляется полоса «Доступна новая версия» с кнопкой
  «Обновить». Программа скачивает установщик и подпись, проверяет подпись
  открытым ключом `packaging/update-key.pub`, который зашит в программу,
  и только потом запускает установщик. Он закрывает старую версию, ставит
  новую и открывает её.
- Подпись делается закрытым ключом. Он хранится только в секретах
  репозитория под именем `UPDATE_SIGNING_KEY`. Без него подменить
  обновление нельзя: подпись не сойдётся, и программа откажется ставить.

## Добавить секрет подписи (один раз)

Закрытый ключ лежит в файле `update-signing-key.secret` в папке проекта
этой сессии Claude. В git его нет и не будет.

1. Откройте в приложении Claude файл `update-signing-key.secret`.
2. Скопируйте всё его содержимое — обе строки целиком.
3. Откройте https://github.com/Sandman-ing/Bolh-Place/settings/secrets/actions
4. Нажмите зелёную кнопку **New repository secret**.
5. В поле **Name** впишите: `UPDATE_SIGNING_KEY`
6. В поле **Secret** вставьте скопированное.
7. Нажмите **Add secret**.
8. Сохраните копию файла в надёжном месте, например в менеджере паролей.
   Если ключ потеряется, уже установленные программы не смогут
   обновляться сами — их придётся переустановить вручную.

Значение секрета GitHub больше никому не показывает, даже вам. Это
нормально.

## Выпустить новую версию

1. Поднять номер версии в `Cargo.toml` (`[workspace.package] version`).
2. Обновить `packaging/release-notes.md`.
3. Слить pull request в `main`. Выпуск появится сам минут через 20.
