# Правила работы в Bolh Place

## Источник правды

[BOLH_PLACE_SPEC.md](BOLH_PLACE_SPEC.md) — утверждённая спецификация. Ничего
сверх неё не додумывать. Нашёл дыру или противоречие — предложи варианты и
спроси владельца. Спецификация меняется только с его согласия.

## Общение с владельцем

- По-русски, коротко и простыми словами. Владелец не программист: всё, что
  ему нужно сделать самому, расписывай по шагам, по одному действию на шаг.
- Если что-то непонятно, задавай вопросы, а не угадывай.
- Длинную работу заканчивай уведомлением о том, что готово.

## Ветки и main

- Работа идёт в ветке `claude/…`.
- В `main` — только через pull request, который сливает сам владелец. Прямо
  в `main` не пушить никогда.
- Каждый этап из раздела 13 спецификации — отдельный pull request. Он
  заканчивается выпуском на GitHub с установщиком, который владелец может
  поставить и проверить руками.

## Коммиты и код

- Сообщения коммитов на русском:
  - первая строка — что сделано;
  - после пустой строки — почему, человеческим языком;
  - в конце — строки авторства, которые требует среда.
- Комментарии в коде на русском, объясняют «почему», а не «что».
- Название модели в коммиты, код и документы не попадает.

## Качество

Это важнее скорости. Перед каждым пушем:

- `cargo fmt --check`;
- `cargo clippy` без предупреждений;
- все тесты проходят;
- свой дифф перечитан с вопросом «что здесь сломается».

Каждое изменение поведения — с тестом. Тест должен падать на старом коде:
это проверяется.

## Платформа

- Цель — Windows 10 и 11, 64 бита.
- Разработка идёт в Linux-контейнере, где нет Windows. Поэтому сборка,
  установщик и проверки интерфейса гоняются в GitHub Actions на
  `windows-latest`. Ядро, которому не нужен экран, тестируется и локально.
- Стек: Rust, интерфейс на GPUI с gpui-component. Версии зависимостей
  закреплены, обновляются по одной и осознанно.
- Библиотеки — только со свободными лицензиями: MIT, Apache, BSD, ISC.

## Секреты

Значения ключей, паролей и токенов не выводить никуда: ни в чат, ни в логи,
ни в git.
